# dna_miner: הוכחת פעולה על rose האמיתי

## המבחן

המכשיר קרא את הקבצים האמיתיים של rose (globals.css בן 1428 שורות,
tarot.ts, wisdom.ts) בלי שום ידע מוקדם על שושנה, והציע DNA.
השווינו מול ה-DNA שנכתב ידנית (identity_extractor).

## תוצאות הכרייה

| שורש | מה המכשיר כרה | ביטחון |
|---|---|---|
| material | parchment + candle-metal + ink + night + gold | 1.00 |
| palette_logic | עוגנים #e8dfc8, #1a1612, #8a5a2b | 0.90 |
| voice | משפטים קצרים, בלי קריאות התפעלות | 0.80 |
| motif | letters/paths (22) כעיקרון מארגן | 0.50 |
| hierarchy | grid-mixed (נכון: הפריסה הנוכחית אינה האצלה) | 0.50 |
| rhythm | 0.2s dominant, share 0.17 (אין קצב נשימה בקוד, נכון) | 0.17 |
| signature | None, סומן needs_human (בכוונה) | 0.00 |

## השוואה מול DNA ידני

- שחזור כולל: 11/15 עובדות מפתח = 73%
- material: 5/5 מלא
- palette: 2/3. המכשיר קרא את דיו ה-light-mode (#1a1612), הידני ציין dark-mode (#14110d). שניהם משפחת דיו.
- motif: 3/4. המספר 22, נתיבים, אותיות. 'עץ' לא נכרה כי הוא לא מופיע במבנה הנתונים.
- voice: 1/3. קוצר משפטים נכרה; צפיפות מקורות מתחת לסף בדגימה המשותפת.

## מה המכשיר מסמן כצריך-אדם (בכנות)

- signature: תמיד. חתימה לא כורים, ממציאים אותה. המכשיר נותן רמזים גולמיים בלבד.
- rhythm: כשאין תבנית קצב קוהרנטית בקוד (share נמוך).

## הלולאה הסגורה

פרויקט קיים -> dna_miner -> DNA מוצע + ביטחון + ראיות + needs_human
-> אישור/השלמת אדם ל-signature -> composer -> מערכת עיצוב שלמה
-> design_scan + detectors לאימות clean_score -> apply להחלה על הפרויקט.

שושנה היא התיק הראשון שנכנס למכונה. כל פרויקט אחר ייכנס אותו דבר.
